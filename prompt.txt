1. 도메인 및 용어/날짜/시트 정의
- 시트 명칭 및 이름 규칙 정의:
  - 현재 시트: 스크립트 '실행 완료 후' 생성되어 1번 위치(Index 0)에 배치되는 `YYYY-MM-dd HH:mm:ss` 이름의 새 시트.
  - 직전 시트: 스크립트 '실행 직전'에 1번 위치(Index 0)에 있던 시트. 실행 후 3번 위치로 이동하며 이름 앞에 `(직전시트)` 태그가 붙음 (`(직전시트)YYYY-MM-dd HH:mm:ss`).
  - 기타 과거 시트: 5번 위치 이후의 보존 시트들. 이름에서 `(직전시트)` 태그가 제거된 pure `YYYY-MM-dd HH:mm:ss` 형태 유지.
- 인정유효기간과 급여개시일: 인정유효기간은 급여개시일과 상이할 수 있다. (인정유효기간 이후 급여개시 가능)
- 변경 계약서와 인정서 갱신:
  - 인정유효기간 종료일(만료일) 이전에 추가 작성된 표준약관은 '변경 계약서'로 취급하며, 인정유효기간은 변경되지 않는다.
  - 인정유효기간 종료일 이후 새로운 인정유효기간 종료일을 가지는 표준약관을 작성하는 것을 '인정서 갱신'이라 한다.
- 급여제공계획서 작성일자: 급여제공계획서 종료일자 한 달 전에 작성되어야 함.
- 종료일 한 달 전의 정의: 기준일이 속한 월의 "전월 1일부터 말일까지"를 의미한다. (예: 종료일이 2026-10-29이면 한 달 전은 2026-09-01 ~ 2026-09-30)
- 결과평가 작성일자: 연 1회, 급여제공계획서 종료일자 한 달 전에 작성되어야 한다.
- 기초평가(낙상, 욕창, 인지) 작성 주기: 반기별 1회 작성. 2회 중 1회는 반드시 '급여제공계획서 종료일자 한 달 전'에 작성되어야 한다.
  - 급여제공계획서 종료일 한 달 전이 상반기일 경우 -> 하반기 기초평가는 상반기 작성달로부터 6개월 후 시행.
  - 급여제공계획서 종료일 한 달 전이 하반기일 경우 -> 상반기 기초평가는 하반기 작성달로부터 6개월 전 시행.
- 욕구사정 작성 주기: 연 1회, '급여제공계획서 종료일자 한 달 전'에 작성되어야 함.

2. 시트 레이아웃 및 상단 컨트롤 명세
- 1행: A1="케어포", B1="연동일시", C1=[드롭다운: "업데이트"]
- 2행: A2="전년도", B2="시트", C2=[전년도 시트 URL 입력란]
- 3행: A3="수급자", B3="기본자료", C3=[구글 드라이브 루트 폴더 URL 입력란]
- 4행: (비어둠)
- 5행 (테이블 헤더):
  No. | 현황 | 수급자명 | 표준약관\n작성일자 | 급여제공계획서\n종료일자 | 낙상위험도\n(상반기) | 욕창위험도\n(상반기) | 인지기능\n(상반기) | 낙상위험도\n(하반기) | 욕창위험도\n(하반기) | 인지기능\n(하반기) | 욕구사정 | 급여제공계획서\n작성일자 | 급여제공계획서\n종류 | 결과평가\n작성일자 | 급여제공계획\n적용기간(시작) | 급여제공계획\n적용기간(종료) | 급여계약기간(시작) | 급여계약기간(종료) | 비고
- 6행부터: 실제 데이터 작성 영역

3. 개발 및 코드 작성 원칙 (필수 준수 사항)

1) 색상 표준 및 교차 색상 규칙
- 데이터 영역(6행 이후)의 기본 바탕색은 기본 `#ffffff`를 허용하며, 가인독성을 높이기 위해 구글 스프레드시트의 기본 교차 색상(흰색 및 연한 회색 조합) 적용을 허용한다.
- 단, 명세서에서 지정한 특수 상태별 색상은 다음 3가지 Hex Color 코드만 엄격히 사용한다.
  * 긍정 컬러: `#d9ead3`
  * 부정 컬러: `#f4ccd0`
  * 중립 컬러: `#cccccc`
- 상태별 색상 조건에 해당하지 않는 일반 셀은 교차 색상 또는 기본 `#ffffff` 배경을 유지하며, 임의의 다른 색상을 지정하지 않는다.
- 전체시트 폰트사이즈를 12px로 하고 좌우상하 모두 가운데 정렬한다.
- 5행까지 행고정, C열까지 열고정한다.
- 헤더행은 배경색을 #34495e, 텍스트컬러를 흰색으로 하고 bold 적용한다.
- 1~3행의 A열과 B열은 배경색을 #1155cc, 텍스트 컬러 흰색으로 하고 bold 적용한다.
- 1~3행의 A, B열만 좌우정렬을 다르게 한다 A열은 우측정렬, B열은 좌측정렬한다.

2) 예외 처리 및 작업 완주 보장 (Fault-Tolerance)
- 특정 행(수급자) 처리 중 데이터 누락, 드라이브 탐색 오류, URL 미입력, 파싱 예외 등이 발생하더라도 전체 스크립트 실행이 중단되어서는 안 된다.
- C2, C3 입력값이 없거나 참조 시트를 찾지 못하는 경우에도 알림창으로 강제 종료하지 않고, 가능한 항목을 처리하며 마지막 데이터 행까지 작업을 완수한다.
- 오류가 발생하거나 값이 누락된 항목은 해당 위치에 에러/미작성 표기를 수행하고 다음 행/열 처리를 계속 진행한다.

3) 로깅 정책 (Comprehensive Issue Logging)
- 의도와 다른 결과 및 오류가 발생한 모든 상황을 Log 시트에 일괄 기록하여 한눈에 파악할 수 있도록 한다.
- 로깅 대상:
  ① 필수 데이터 누락: 수급자명 결손, 적용기간/인정유효기간 필수 참조 데이터 미입력 등
  ② 파일 미매칭 / 날짜 형식 오류 / URL 미입력: 드라이브 URL 미입력 또는 매칭 파일 없음, 파일명/데이터 내 날짜 형식 불일치 등
  ③ 미작성 및 갱신 필요 건: 작성 의무 기간 내 미작성, 인정유효기간 갱신/계획서 작성 필요 상태 등
  ④ 코드 실행 중 런타임 오류(Exception) 발생 건
- Log 시트 작성 구조: 
  [발생일시 | 수급자명 | 행 번호(Row) | 열/항목명(Column) | 오류/이슈 구분 | 상세 내용 및 조치 필요사항]

4) API 호출 최소화 및 메모리 캐싱 극대화
- 구글 스프레드시트 API 및 구글 드라이브 API 호출(getValue, getRange 등)은 타임아웃 방지를 위해 최소화한다.
- 시트 데이터, 서식, 드라이브 파일 구조 등은 실행 초기에 메모리(Map, Object, Array)에 일괄 래핑(Caching)한 후 처리한다.

5) 반복문 작성 및 함수형 프로그래밍 지침
- for, while 등 전통적 반복문은 성능상 이점이 입증되는 특수한 경우를 제외하고 엄격히 금지한다.
- Array.prototype.map, filter, reduce, forEach, find, some, every 등 ES6+ 배열 메서드를 적극 활용한다.

6) 최신 ES6+ 문법 활용
- var 사용을 엄격히 금지하며 const와 let만 사용한다.
- 화살표 함수(Arrow Function), 구조 분해 할당(Destructuring), 널 병합 연산자(??), 옵셔널 체이닝(?.), 템플릿 리터럴(` `), Object/Map 메서드 등 modern JavaScript 문법을 전면 적용한다.

7) 주석 작성 제약 사항
- 각 파이프라인 Step 및 주요 서브 함수 시작점에는 반드시 단계 설명 주석을 명시한다.
- 코드 내 주석은 간결하고 명확하게 자주 작성하되, 명세서에 언급된 도메인 용어(예: 인정서 갱신, 종료일 한 달 전, 변경계약서 등)가 등장하는 지점에는 해당 용어의 의미와 다른 도메인과의 연관성을 설명하는 주석을 반드시 남긴다.

4. GAS 실행 파이프라인 및 핵심 로직

Step 1: C1 드롭다운 감지 및 트리거 (onEdit)
- onEdit(e) 이벤트를 활용하여 사용자가 C1 셀에서 "업데이트"를 선택하는 즉시 감지한다.
- 프로그램적 값 변경(실행 직후 C1 값 갱신 등)으로 인한 `onEdit` 이벤트의 연쇄적 재귀 호출(중복 실행)을 방지하는 안전 플래그(PropertiesService 등 활용)를 적용한다.
- C1이 "업데이트"로 변경된 경우, "하단의 케어포연동 시트와 구글드라이브(표준약관, 급여제공계획서, 급여제공 결과평가)가 모두 최신이어야 합니다. 진행하시겠습니까?" Confirm 팝업을 띄운다.
- 사용자가 확인을 누르면 runCareforPipeline 함수를 1회 실행하며, 실행 직후 C1 셀에 단순 문자열이 아닌 **"업데이트" 항목이 포함된 데이터 유효성 검사 규칙(드롭다운)**을 유지하면서 현재 시트 이름(`YYYY-MM-dd HH:mm:ss`)을 설정한다.
- 코드 실행 직전 '1번 시트(Index 0, 직전 시트)'의 C2(전년도 시트 URL) 및 C3(드라이브 URL) 값을 읽어온다.
- C2, C3 값이 없더라도 실행을 중단하지 않고, 비어있는 참조 항목에 대한 로그를 수집하며 다음 파이프라인을 계속 진행한다.
- 'Log' 시트 존재 여부를 확인하여 없으면 생성하고, 기존 내용이 있다면 초기화한다.

Step 2: 드라이브 전체 파일 구조 메모리 캐싱 (성능 최적화 - 필수)
- C3 구글 드라이브 URL이 존재할 경우 하위 전체를 1회 스캔한다. (C3가 없으면 스킵 후 로그 기록)
- Key: "수급자명_폴더명", Value: { fileName: "YYYY-MM-dd.pdf", fileUrl: "...", fileDate: "YYYY-MM-dd" } 형태의 JS Map 객체 메모리에 일괄 Caching한다.
- 파일명에서 정규식(\d{4}-\d{2}-\d{2})을 추출하며, 동일 폴더 내 여러 파일이 있을 경우 가장 최근 파일(수정일 또는 파일명 날짜 기준)을 바인딩한다.

Step 3: 케어포연동 시트 데이터 읽기 및 직전 시트 메타데이터 매핑
- '케어포연동' 시트의 11행부터 데이터 전체를 읽어온다.
- A열: No. (숫자가 유효한 정수인지 검사하며, 정수가 아니거나 빈값인 시점을 데이터 종료로 인식)
- B열: 현황 -> `수급중` 포함 시 긍정컬러(`#d9ead3`), `계약해지` 포함 시 부정컬러(`#f4ccd0`), `보류` 포함 시 중립컬러(`#cccccc`), 그 외/빈값은 `불명`으로 표기하고 부정컬러(`#f4ccd0`) 적용
- C열: 수급자명 -> '(김효정)' 같은 괄호 텍스트 제거, trim 및 개행 제거하여 고유 Key로 사용 (수급자명이 비어있는 경우 해당 행과 열의 에러내용을 로그에 기록.)
- D열 이후: 기초평가 및 급여제공계획 관련 원천 정보
- 직전 시트(실행 직전의 1번 시트) 맵 생성: 수급자명을 Key로 하여 각 셀의 단순 값(Value), RichTextValue(하이퍼링크 정보 포함), 배경색(Background), 글자색(FontColor), 메모(Note), 조건부 서식 규칙(ConditionalFormatRules)을 수급자별로 메모리에 Caching한다.

Step 4: 항목별 데이터 추출 및 연산 (try-catch 기반 예외 분리 및 완주 보장)
- 수급자별/항목별 연산은 try-catch 블록으로 세분화하여, 런타임 오류나 데이터/URL 누락 발생 시 해당 [수급자명 / 행 번호 / 열 이름 / 에러 메시지]를 로그 배열에 수집하고 마지막 데이터 행까지 멈춤 없이 루프를 지속한다.

1. 급여제공계획 적용기간 시작/종료 (현재 시트 P, Q열 / 케어포연동 시트 L열 원천 데이터 파싱):
   - 케어포연동 시트 L열 원천 데이터 영역에서 (YY.MM.dd~YY.MM.dd) 형태 추출 및 YYYY-MM-dd 가공.
   - 케어포연동 시트 L열 원천 데이터 영역에서 (YY.MM.dd~YY.MM.dd) 형태의 텍스트가 전년도 시트에서 해당 수급자의 동일 항목(P,Q열) 값을 가져옴.
   - 전년도 시트에도 없으면 직전 시트에서 해당 수급자의 동일 항목에 YYYY-MM-dd 형태의 텍스트가 있으면 가져옴
   - 최종적으로 YYYY-MM-dd 형태의 값이 저장되어야 함.(컬러적용 없음:흰색) 아닐 시, "오류"(부정컬러 #f4ccd0) 처리 후 해당 행과 열의 에러내용을 로그에 기록.
2. 급여제공계획서 종료일자 (현재 시트 E열):
   - 직전 시트에 존재하는 수급자면 직전 시트의 값/서식을 그대로 이관.
   - 직전 시트에 값이 없거나 형태가 YYYY-MM-dd가 아닐 시, 전년도 시트의 '급여제공계획 적용기간(종료)' 값을 가져옴.
   - 전년도 시트에도 값이 없거나 YYYY-MM-dd 형태가 아니면 현재 생성 중인 시트의 급여제공계획 적용기간(종료) 값을 사용.
   - 최종적으로 YYYY-MM-dd 형태의 값이 저장되어야 함.(컬러적용 없음:흰색) 아닐 시, "알 수 없음\n(직접입력필요)"(부정컬러 #f4ccd0) 처리 후 해당 행과 열의 에러내용을 로그에 기록.
3. 표준약관 작성일자 (현재 시트 D열):
   - 전년도 시트의 인정유효기간(종료)가 없거나 YYYY-MM-dd가 아니면 "알 수 없음\n(직접입력필요)"(부정컬러 #f4ccd0) 처리 후 해당 행과 열의 에러내용을 로그에 기록.
   - 전년도 시트의 인정유효기간(종료) YYYY가 올해가 아니면 빈칸.
   - 올해일 경우: 현재 일자가 전년도 시트 종료일 포함 월의 전월보다 이전이면 "갱신필요".
   - 전월에 포함되거나 이후이면 캐싱된 드라이브 Map에서 [수급자명_표준약관_인정유효기간갱신] 최신 파일 조회.
   - 파일 날짜 YYYY가 올해이면 YYYY-MM-dd 표기 + 하이퍼링크 삽입(긍정컬러 #d9ead3). 아니거나 파일 없으면 "갱신필요"(부정컬러 #f4ccd0).
4. 기초평가(낙상, 욕창, 인지) & 욕구사정 (현재 시트 F~L열 / 케어포연동 시트 원천 데이터 파싱):
   - 낙상위험도(상반기): 케어포연동 시트 E열 원천 데이터 매핑
   - 낙상위험도(하반기): 케어포연동 시트 F열 원천 데이터 매핑
   - 욕창위험도(상반기): 케어포연동 시트 G열 원천 데이터 매핑
   - 욕창위험도(하반기): 케어포연동 시트 H열 원천 데이터 매핑
   - 인지기능(상반기): 케어포연동 시트 I열 원천 데이터 매핑
   - 인지기능(하반기): 케어포연동 시트 J열 원천 데이터 매핑
   - 욕구사정: 케어포연동 시트 K열 원천 데이터 매핑
   - YYYY.MM.dd -> YYYY-MM-dd 가공(긍정컬러 #d9ead3).
   - YYYY.MM.dd 형태가 없을 경우 원래 텍스트를 가져옴.
   - 가져온 텍스트가 "미작성"이고 현재 시점이 작성 의무 기간이면 부정컬러(#f4ccd0), 미작성이지만 의무 기간이 아니면 중립컬러(#cccccc) 적용.
   - 그 외 중립컬러 적용
5. 급여제공계획서 작성일자 & 종류 (현재 시트 M, N열 / 케어포연동 시트 L열 원천 데이터 파싱):
   - 케어포연동 시트 L열 원천 데이터에 공단작성(YYYY.MM.dd) 텍스트가 있으면 YYYY-MM-dd로 가공.
   - 캐싱된 드라이브 Map의 [수급자명_급여제공계획서] 최신 파일 날짜와 일치 시 링크 삽입(긍정컬러 #d9ead3). 불일치/없음 시 YYYY-MM-dd\n(파일오류)(부정컬러 #f4ccd0).
   - 케어포연동 시트 L열 원천 데이터에 미작성 텍스트가 있으면 "미작성"으로 표기하며, 작성 의무 기간이면 부정컬러(#f4ccd0) 적용.
   - 케어포연동 시트 L열 원천 데이터에 계약해지 텍스트가 있으면 "계약해지" 표기(중립컬러 #cccccc).
   - 그 외의 경우 케어포연동 시트 L열 원천 데이터 값을 그대로 사용.
   - 종류: 문맥에 따라 "방문요양" 또는 "방문목욕" 표기하며, 작성일자의 긍정/부정/중립 컬러를 그대로 따름.
6. 결과평가 작성일자 (현재 시트 O열):
   - 직전 시트에 값이 있으면 해당 값과 RichText/서식을 유지.
   - 현재 시점이 작성 의무 기간(종료일 한 달 전)이 아니면 직전 시트에서 이관된 상태 그대로 유지.
   - 작성 의무 기간일 경우: 캐싱된 드라이브 Map의 [수급자명_급여제공결과평가(모니터링)] 최신 파일 조회.
   - 파일 날짜 YYYY가 올해이면 YYYY-MM-dd 표기 + 링크 삽입(긍정컬러 #d9ead3).
   - 파일이 없거나 올해가 아닌 경우:
     - 기존 직전 시트 텍스트가 있을 시: 기존 텍스트에 개행 후 (파일오류) 추가 표기(부정컬러 #f4ccd0).
     - 기존 직전 시트 텍스트가 없을 시: "미작성" 표기(부정컬러 #f4ccd0).
7. 수동 기입 및 직전 시트 승계 항목 - 인정유효기간(시작/종료 - 현재 시트 R, S열) 및 비고(현재 시트 T열):
   - 완벽 승계 원칙: 직전 시트에 해당 수급자의 데이터가 존재할 경우, 단순 텍스트(Value)뿐만 아니라 하이퍼링크(RichTextValue), 배경색(Background), 글자색(FontColor), 메모/주석(Note)을 통째로 새 시트 해당 위치에 복원하여 이관한다.
   - 직전 시트에 값이 없을 경우:
     - 표준약관 작성일자가 빈칸이면 전년도 시트 값 가져옴.
     - 표준약관 작성일자에 YYYY-MM-dd가 있는 경우: 입력 값이 있으면 긍정컬러(#d9ead3), 빈칸이면 "미작성"(부정컬러 #f4ccd0).
     - 그 외의 경우 "알 수 없음\n(직접입력필요)" 표기(부정컬러 #f4ccd0) 및 [필수 데이터 누락] 로그 기록.

Step 5: 새 시트 생성, 데이터 일괄 작성, 서식 적용 및 로그 일괄 저장 (Batch Operation)
- 실행 시점 현재 시간 기준 `YYYY-MM-dd HH:mm:ss` 이름으로 새 시트(현재 시트) 생성.
- 상단 1~3행 컨트롤 바 및 5행 헤더 레이아웃을 생성한다.
- 6행부터 메모리 배열 데이터를 setValues() 및 setRichTextValues()로 일괄 입력한다.
- 직전 시트에 설정되어 있던 조건부 서식 규칙(getConditionalFormatRules)을 읽어와 현재 시트 데이터 영역(6행 이후)에 동일하게 재적용(setConditionalFormatRules)한다.
- 수집된 필수 데이터 누락, URL 미입력, 파일 미매칭 및 런타임 오류 로그를 'Log' 시트에 일괄 입력한다.

Step 6: 시트 순서 정렬, 이름 재설정 및 과거 시트 자동 정리
- 시트 순서 및 이름 재설정:
  1. `현재 시트`: 맨 앞(1번 위치) 배치, 이름은 `YYYY-MM-dd HH:mm:ss`
  2. `케어포연동`: 2번 위치 배치
  3. `직전 시트`: 3번 위치 배치, 기존 이름 앞에 `(직전시트)` 접두사 추가 (예: `(직전시트)YYYY-MM-dd HH:mm:ss`)
  4. `Log`: 4번 위치 배치
  5. `기타 과거 시트들`: 5번 위치 이후 배치. 이전에 붙어있던 `(직전시트)` 태그가 있다면 제거하여 pure `YYYY-MM-dd HH:mm:ss`로 원복 및 날짜 기준 오름차순 정렬.
- 정렬 후, 4번 시트 이후(5번 위치부터 시작되는 과거 기타 시트 목록) 중 상위 2개만 보존하고 나머지는 자동 삭제한다.
- 모든 파이프라인 및 시트 정리가 완료된 직후 사용자에게 작업 완료를 알리는 UI 얼러트(`SpreadsheetApp.getUi().alert("완료", "모든 데이터 연동 및 정리가 완료되었습니다.", SpreadsheetApp.getUi().ButtonSet.OK);`)를 출력한다.
